# 废土回声 v0.2 · 可行走地堡 / 手机操作 / 联机存档

新版默认端口为 **8788**，可与旧版 8787 同时运行。

这是依据 GDD v1.0 的 P0 游戏继续开发的版本。四职业、边缘废土、掘地者与原有成长数值保留；本次将地堡从菜单改成共享的可移动场景，并重做手机操作与保存系统。

## 开始游戏

macOS 双击 `启动游戏.command`。Windows 运行 `start-game.bat`。或使用 Node.js 20+：

```sh
node server.mjs
```

打开 http://localhost:8788 。游戏运行不需要安装 npm 依赖。保持服务器终端打开；`Control+C` 会保存检查点再退出。端口冲突可使用 `PORT=8789 node server.mjs`。

## 在地堡生活与整备

进入游戏后，角色直接位于余烬号内部。沿中央走廊穿过门口进入各房间。所有升级都需要走近实体设施，按 **E** 或右侧 **互动** 圆钮。靠近时会显示效果与消耗，没有升级选择菜单。

| 地点 | 互动作用 |
|---|---|
| 生活区的四个装备柜 | 切换暗杀者、卫兵、术士或火炮手 |
| 舰桥主控终端 | 升级主控室，决定其他设施上限 |
| 舰桥通讯台 | 打开联机通讯，可邀请或加入小队 |
| 工坊控制台 | 提高武器工坊等级 |
| 武器锻造台 | 强化当前职业武器，检查费用与突破条件 |
| 医疗舱核心 | 升级医疗设施，提高死亡奖励保留比例 |
| 两个医疗工作台 | 分别制作治疗针与抗辐射药 |
| 训练区四台训练器 | 用属性点提升生命、攻击、防御、暴击 |
| 反应堆控制台 | 升级能源站，提高燃料容量 |
| 右侧气闸 | 确认准备；全员准备后房主再次互动出发 |

地堡具备服务器碰撞检测、门口通行、实时队友位置、房间标记和小地图。不同玩家各自保留角色与设施成长；共享地堡空间不等于共享个人资源余额。

## 手机与 PC 操作

“操作”设置提供 **自动识别 / 手机触摸 / PC 键鼠**，选择保存在当前设备。自动模式根据粗指针能力和触摸点识别，而不是只按窗口宽度判断。

- 手机左侧摇杆移动，右侧大圆按钮按住攻击，拖动瞄准；周围圆形按钮释放三个技能、闪避、互动和药剂。
- 不拖动攻击按钮时可自动瞄准附近敌人，设置中可关闭。支持同时移动、攻击、施法的多指输入。
- 右侧操作按钮保持固定 DOM 节点，战斗快照不会替换它们或中断长按。取消触摸、切后台、改变场景会清空按键，避免角色持续乱跑。
- 支持横屏与竖屏、安全区边距、按钮大小调整。窄屏会进一步缩小操作区域；较矮横屏将队友列表收进“小队”窗口以留出战斗空间。
- PC：WASD 移动，鼠标瞄准，左键攻击；右键或 1 第一技能，2 / 3 其他技能；空格闪避；E 互动；Q 治疗，R 抗辐射。
- 卫兵长按攻击固守；术士长按吟唱蓄力，松开释放贯穿射线。救援与回堡需要持续按住互动 2.5 秒。

生命条旁的紧凑图标栏显示固守、壁垒、无敌、技能增益、毒刃、蓄力、药剂保护、中毒、减速、高辐射和倒地状态。显示剩余秒数，负面状态优先；超过六项时汇总到“+”图标。鼠标悬停或触摸图标查看说明。

敌人会根据移动/追击方向转向：横向镜像、纵向前后视图，以及飞行敌人朝向旋转；状态与朝向随服务端快照同步。

## 联机流程

1. 点击“小队”或走到通讯台，创建正式或演练房间。
2. 复制邀请链接。若本机以 localhost 访问，邀请会尝试使用局域网地址；也可手动输入房间码。
3. 队友使用同一 Wi-Fi，打开房主机器的局域网 IP 与端口 8788。不同玩家需独立浏览器身份。
4. 真人在右侧气闸集合并确认准备，房主再次互动发起行动。空位由 AI 补齐四人。离开集合区、掉线或更换职业会取消准备。
5. 新玩家可在探索期间加入房间，在地堡走动整备，等待探索中的队友返航；不会强行插入进行中的战斗。
6. 战斗结束后任意队员可确认返回，或等待 15 秒自动返回共享地堡气闸。

断线立即由 AI 接管，席位保留 60 秒，房主自动迁移至在线队员。房主可移除离线席位。超过保留期释放席位，但该玩家的本次奖励仍根据原参与记录结算。网络输入包含场景 ID 和递增序号，丢弃过期场景与乱序操作。UI 显示连接延迟，并对角色位置进行视觉平滑。

同一身份在多个标签页打开时，最新标签页接管，旧页面停止自动抢占；可点击“在此继续”切回。互联网访问仍需要自行部署 HTTPS 与可访问的服务器；本项目未发布公网服务。

## 保存与恢复

- **自动保存**：每 5 秒保存角色成长、资源、职业、地堡位置、房间及探索检查点。
- **手动保存**：顶部保存按钮，或“操作 → 保存与恢复 → 立即保存”。
- **重启恢复**：服务器正常退出会保存；意外终止最多丢失最近约 5 秒的检查点进度。重启后原房间和战斗会恢复，在玩家重新连接前暂停，不计算离线战斗时间。
- **仅关闭浏览器**：服务器仍在运行，联机世界继续由 AI 接管；全员离线 60 秒按团灭结算。这与停止服务器后的检查点恢复不同。
- **下载成长备份**：导出不含身份令牌的 JSON，保存永久成长和地堡位置；不包含正在进行的房间战斗。
- **读取成长备份**：必须回到地堡，选文件后先显示覆盖说明，再确认恢复。服务器验证版本、字段范围、等级、属性点和设施约束。只替换当前玩家成长，不改动队友。

存档位于 `data/profiles.json` 与 `data/rooms.json`。浏览器用本地身份令牌找到自己的存档；不要清除站点数据。换设备或从旧版 8787 切换到新版 8788 时，浏览器身份相互独立，可使用成长备份恢复。操作布局设置保存在设备端。`data/` 是运行数据，不包含在源码压缩包中。

## 验证

```sh
node --test tests/*.test.mjs
python3 reference/numeric_validation.py
```

测试覆盖原有战斗机制、地堡门与墙碰撞、设备识别、多指输入、实体设施交互、四人同步、准备门槛、旧场景输入隔离、房主迁移、重连、探索期间加入地堡、存档校验、状态栏、敌人朝向及服务器重启恢复。还包括完整 10 级小队的“探索 → 击败掘地者 → 带蓝图返航”模拟。

可选 UI 测试：安装开发依赖后执行 `npm run test:ui`。游戏运行不需要这些开发依赖。独立 DOM 运行时测试验证启动、触摸自动识别、手动切换布局、长按节点不被快照替换、双指独立释放、状态栏、保存操作和小队界面。场景离屏渲染已目视检查。本环境原生浏览器自动化仍无法启动，因此不将这些测试表述为真实手机触摸或浏览器视觉验收。

## 原始方案差异与范围

- 保留完整原始 `game_config.json`。原资料汇总称 6 首领／52 总条目，但实际列出 7 首领，总计 53。P0 使用 7 基础怪、3 精英、掘地者，共 11 条目。
- 术士普攻按正文 110% 实现；原数值脚本用了 120%，且实际输出 21 条 PASS 却标注 20/20。原脚本原样保留，运行逻辑另有测试。
- 采用文档生产检查中的权威服务器要求，房主只负责组织出发；战斗、购买距离与奖励都由服务器验证。
- 未给定精确参数的 P0 细节：治疗针恢复 40% HP、冷却 10 秒；抗辐射药降低 40 辐射并保护 30 秒；两种补给各 40 币；净化塔范围 170 地图单位、净化 18/秒、恢复 2.5% HP/秒；能源站每级燃料容量 +2；医疗舱每级提高死亡结算 2 个百分点，上限 58%。
- 四人包含 AI，因此精英／首领采用四人基准 HP。AI 租借队友按领队当前职业等级与武器等级生成。
- 像素美术为程序绘制，尚非 GDD 第 13 节完整 PNG 动画帧组；场景家具当前为装饰，房间墙体与门负责移动碰撞。
- 未包含 P1/P2：区域 2–5 可玩地图、转职、五部位装备与模块、科技树、悬赏、防御战、深渊及阿克纳最终战。

## 源码结构

- `server.mjs`：房间、权威同步、就绪流程、断线管理、存档检查点。
- `save.mjs`：成长备份与恢复校验。
- `public/core.mjs`：战斗、成长、经济、结算。
- `public/hub.mjs`：地堡地图、实体设施与碰撞。
- `public/hub-render.mjs` / `render.mjs`：地堡、荒野、像素角色和敌人方向。
- `public/controls.mjs` / `status.mjs`：设备布局、多指归属、状态图标数据。
- `public/app.mjs` / `style.css`：游戏界面、操作与联机客户端。
